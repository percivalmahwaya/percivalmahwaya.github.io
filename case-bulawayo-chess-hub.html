Bulawayo Chess Hub: software a real association runs on.

Problem

Chess clubs need to register members, pair rounds fairly, keep ratings and take entry fees. The Bulawayo Chess Association needed that in one system with public standings and no spreadsheet.

Constraint

Payments run through Paynow (EcoCash and InnBucks). Hosting is Railway. Every model is scoped to an association so more clubs can use the same deployment.

Decisions
  • Tournament sections (Open, Ladies, Developmental) pair independently but share one round schedule and board numbering.
  • The model keeps its historical name, Association, while the interface says "club", because five other apps hold foreign keys to it. /associations/ redirects to /clubs/.
  • Publish a public /security/ page listing what is and is not secured, with no claim I cannot verify.
  • Add qa_production.py, which checks the deployed system (live variables, boot guards, HTTPS) and not only the code.
  • Require two-factor authentication for administrators.
Result

260 automated tests with every app covered. Swiss pairing with Buchholz tiebreaks, an Elo engine (K=32, start 1200), Lichess sign-in, PGN replay, CSV and print export.

Sources: README.md, CHANGELOG.md, members/middleware.py in bcaChessHub.

What went wrong

Two security faults and one outage reached production.

  • An unverified Paynow callback hash and a sandbox-mode default left a free-approval endpoint reachable. Closed on 2026-09-13/15.
  • On 2026-09-06 a Railway Free-plan credit limit took the site down. Postgres sat in a separate project, so production had been running on ephemeral SQLite. I moved to the Hobby plan, put Postgres in the same project and rotated the secret key out of source.
